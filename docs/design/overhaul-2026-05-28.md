# Festie Design Overhaul Proposal

**A decision document for the product owner**
Surfaces covered: Web (TanStack + Tailwind) and Mobile (Expo / React Native)

---

## 1. Executive Summary

**Recommendation: adopt "Refined Evolution — Stagelight" (avg 7.5/10), but split it into two explicitly-scoped tracks before any work lands.** Festie's identity is already good — a cohesive near-black canvas, a learned three-color priority language (coral/aqua/amber), a 130-token CSS-variable system, and verified WCAG AA contrast. The problem the audit actually documents is *rhythm*, not *look*: off-scale type sizes, hardcoded hexes that bypass the theme, cramped 320px layouts, and admin tables that overflow mobile. Stagelight fixes exactly these with zero new visual language and the lowest migration risk, building directly on the just-landed Tailwind migration (commit `afe5222`).

**However, two judge concerns are correct and must reshape the plan before it ships.** First, the proposal's "we touch nothing else" framing is dishonest about scope — the responsive nav remapping, the admin table→card rewrite, and the new mobile `useTokens()` hook are net-new engineering, not token promotion. Second, two of its headline accessibility "fixes" are solving problems the code *already solved* (verified: the global reduced-motion catch-all exists at `animations.css:108-117`; SetCard focus is already card-level at `SetCard.tsx:216-221`). We therefore recommend Stagelight's **token-discipline pass as P0 (unimpeachable, ship immediately)** and treat its layout/nav/mobile-build work as **P1/P2 features judged on their own merits** — with the genuinely-deferred field-legibility gap (sunlight mode) called out as an open question, not silently dropped.

## 2. Current State Audit

Synthesized from six surface audits. Severity in brackets.

### Web Design System
A mature, centralized system: 130+ CSS custom properties, full dual-theme support, 9 primitives with 50+ Storybook stories, dynamic WCAG-AA enforcement on stage badges. The gaps are all **consistency leaks**, not architecture:
- **[HIGH] Light-theme hardcode** — day-tab-underline is pinned to `#c01d3a !important` in `light-theme.css:185-188`, overriding the priority-want token and breaking themability.
- **[HIGH] Skeleton hardcoded rgba** — `CardsSkeleton.tsx:24` and `TimelineSkeleton.tsx:32,48` bake in `rgba(...)` literals instead of tokens; color changes won't propagate.
- **[HIGH] Missing error-ring token** — `Input.tsx:66` hardcodes `focus-visible:ring-[rgba(255,51,102,0.15)]`; no token exists.
- **[MED] Off-system stage fallback** — `StageBadge.tsx:81` returns hardcoded `#b3b3b3`.
- **[MED] No central design docs**; **[LOW] off-scale `duration-250`** at `StageBadge.tsx:17` (token set is 120/200/320).

### Web Core Experience
Strong information hierarchy across six views (Cards, Grid, Timeline, Picks, Compare, Festival Mode). Consistent priority colors, sophisticated PX_PER_MIN timeline math, polished vaul detail drawer. Issues are mostly responsive polish:
- **[MED] Crew shown as count-only** ("N going") with no avatars on cards.
- **[LOW] Grid stage columns** `min-w-[110px]` with no upper bound → illegible on 1920px+.
- **[LOW] Detail panel** can touch the edge at 1024–1440px (no max-width cap for that band).
- **[LOW] Timeline legend not sticky**; **[LOW] verbose per-section empty states** in Picks.

### Crew / Social
Visually consistent, well-instrumented (ARIA, loading/empty states, 44px targets, real-time balances). Refinement-level issues:
- **[MED] Crew tab bar** relies entirely on horizontal scroll; `-mx-1`/`pr-4` inconsistent <320px.
- **[MED] Expense "split between" pills** have no max-height → form pushes submit button off-screen with 10+ members.
- **[LOW]** Poll "my vote" vs "winning" differ only by opacity (color-vision risk); invite-copy copies a full URL not the 6-char code.

### Account / Admin / Auth
Strong form accessibility and glass-card consistency, but admin density breaks at mid widths:
- **[HIGH] Admin stat grid** jumps `1 → 4` columns with no tablet tier → large gaps <768px.
- **[HIGH] Admin users table** (6 cols) overflows <1024px; action buttons stack and break rows.
- **[HIGH] Auth inputs are `text-center`** — a WCAG 1.3.2 (Meaningful Sequence) violation and a scannability regression.
- **[MED]** Account settings = 6 stacked sections, no tabs/accordion; admin filter rows wrap on tablet.

### Mobile (Expo)
A thin shell, not a parity app. **This is the single biggest scope reality.**
- **[HIGH] Navigation divergence** — mobile has 4 bottom tabs (Timeline/Picks/Crew/Account); it has **no** `/cards`, `/grid`, `/festival-mode`, `/wrap`, `/compare`, or `/admin`. Most screens are "Coming soon" placeholders with one real component (`FestivalList`).
- **[HIGH] No styling layer** — every screen re-types spacing/color/radii via inline `StyleSheet.create()`; no theme hook, no component library.
- **[MED]** No glass/animation parity; no mobile UI state (sheets/modals); minimal memoization.

### Cross-Cutting (a11y / responsive)
Centralized Zustand stores and shared tokens are genuine strengths. Real gaps:
- **[HIGH] Responsive padding** is cramped at 320/390/430px (day tabs, search) and lives in hard-to-audit route CSS.
- **[HIGH] Light-theme contrast unvalidated** — `ensureDarkBgContrast()` only targets dark backgrounds; inactive chips on `#f5f5f7` were never axe-checked.
- **[VERIFIED CORRECTION] Reduced-motion is NOT a gap on web** — `animations.css:108-117` already has a global `*, *::before, *::after` catch-all disabling all animation/transition under `prefers-reduced-motion`. The per-keyframe gating some directions propose is unnecessary on web (it *is* a real gap on RN).

## 3. The Three Directions

| Direction | Score | One-line thesis | Key trade-off |
|---|---|---|---|
| **Refined Evolution — "Stagelight"** | **7.5** | The brand is good; the rhythm is inconsistent — discipline it, don't repaint it. | Lowest risk and most portable; but under-delivers on outdoor/sunlight legibility and contributes no new energy. |
| **Festie Editorial — "The Programme"** | 7.3 | The lineup is content; strip the glass/glow and let a strict type scale + whitespace carry hierarchy. | Most coherent *system* (collapses 6 button variants → 3, two focus rings → 1); but it's effectively a full rewrite + a density engine + recolored muscle-memory priority hues, and ships several **unverified-and-failing** light-theme contrast values. |
| **Bold Festival Identity — "Mainstage After Dark"** | 6.5 | The sun drops and the lights hit — neon-on-night, poster type, a center "Now" FAB. | The right outdoor instincts and a unified nav vision; but bundles necessary a11y fixes with a contested reskin, adds two new fonts + a 5th brand color, and ships **three concrete WCAG failures** (border tints 1.88–2.93:1, white-on-ultraviolet 4.36:1, light aqua 4.15:1). |

**Why not Editorial (7.3), despite being the most principled system?** Its diagnosis is real and verified, but its scope is a multi-sprint rewrite resting on two false premises about the repo: it claims one SetCard renders on both platforms (impossible — web is Tailwind JSX, mobile is RN StyleSheet, separate render trees) and that "tokens come straight from @festie/shared" (false — verified `colors.ts` is a one-way *extraction* from `theme.css`; web does not import it). Its accessibility judge independently computed that `#7C7C95`, light saffron `#C8761A`, and light priority `#0E8577`/`#B5791A` **fail AA** — it ships an unvalidated palette as if final. The risk-adjusted value of a verified, low-churn discipline pass beats a higher-ceiling rewrite built on shaky premises.

**Why not Mainstage (6.5)?** Its core premise ("visually timid, must be louder") is taste asserted as user need, and it welds genuinely-good remediation to a contested neon reskin with three measured WCAG failures and a from-scratch mobile build mislabeled as a "restyle."

## 4. Recommendation & Rationale

**Win: "Stagelight," re-scoped into a P0 token-discipline track and P1/P2 layout tracks.**

It is the most Rams-aligned move a mature system can make: palette frozen, families frozen, the 9-step ramp frozen, radii/z-ladder/motion frozen. Net-new tokens are *promotions of values that already exist hardcoded in source* — every one verifiable in the codebase. It builds on the landed Tailwind migration and is the only direction whose token math is genuinely portable to RN today (verified: `@festie/shared` exposes fontSize/spacing/radii as raw numbers and motion as both cubic-bezier strings *and* 4-tuples for Reanimated).

### Addressing the toughest concern head-on

**Concern (scope honesty + false a11y premises):** *"'Touch nothing else' undersells real net-new design, and two headline a11y fixes solve already-solved problems."*

This is correct, and we accept it as a structural change to the plan rather than a footnote:

1. **We strike the false a11y "fixes."** Verified against source: (a) the global reduced-motion catch-all already exists (`animations.css:108-117`) — we will **not** hand-roll per-keyframe `@media` wraps on web (that risks *less* coverage than the universal rule); the real reduced-motion gap is **RN-only**, where there is no CSS media query and each Reanimated animation must check `AccessibilityInfo.isReduceMotionEnabled`. (b) SetCard focus is **already** card-level (`SetCard.tsx:216-221`: `absolute inset-0` + `outline-offset-[-2px] rounded-[inherit]` traces the full card). We will **not** add an outer ring (that creates the double-ring artifact the proposal itself lists as a risk); the action is downgraded to "verify the existing inset ring is visible enough."

2. **We split the tracks so each is judged honestly.** **P0** is pure token promotion — unimpeachable, near-zero visual risk, shippable this week. **P1/P2** (admin table→card collapse, mobile `useTokens()` hook, the segmented "View" control) are **acknowledged net-new engineering** with their own acceptance criteria, not smuggled under a "discipline" banner.

3. **We refuse to ship unverified contrast.** The light-theme status overrides and any new `ensureDarkContrast()` helper are **gated behind an axe-on-light-theme CI run** before merge — because the audit confirms light theme was never validated.

4. **We name the one thing Stagelight genuinely defers: sunlight legibility.** The brand-fit judge is right that a near-black canvas + an even-darker sticky band (`#05050c`) is the worst case under glare, and the "what's playing NOW" moment is frozen. We do **not** pretend this is solved. It moves to Open Questions as an explicit product decision (P2 "Daylight/Boost mode"), so the field gap is visible, not buried.

The honest verdict: Stagelight's **token pass is a 9/10 move**; its bundled layout work is good but additive. By separating them we keep the unimpeachable part unimpeachable and stop holding it hostage to the larger work.

## 5. Proposed Design System (Stagelight)

All values map to **both** Tailwind (`@theme` CSS vars in `theme.css`) and React Native (raw numbers / hex / bezier tuples in `@festie/shared/src/tokens`). **A note on sync:** today `colors.ts` is a one-way manual extraction from `theme.css` (verified header comment). Stagelight's P0 includes a lightweight token-sync check (a test asserting the TS mirror matches the CSS vars) so the two copies cannot silently drift — this is a prerequisite, not optional.

### 5.1 Color — KEEP every brand hue exactly

|---|---|---|---|---|
| Canvas | `--color-bg-primary` | `#080810` | `#f5f5f7` | unchanged |
| Secondary bg | `--color-bg-secondary` | `#0e0e1a` | `#eeeef2` | unchanged |
| **Sticky band (NEW)** | `--color-bg-sticky` | `#14142a` | `#ffffff` | **DECIDED: elevate (lighter than canvas) + subtle shadow** — headers read as a raised toolbar. Pair with `--shadow-sticky` (see 5.3). |

**New tokens (the audit's missing four + aliases):**
- `--color-coral-ring: rgba(255,51,102,0.15)` — replaces `Input.tsx:66` hardcode. **Rule:** the ring is *never* the sole focus affordance — it is always paired with a solid border/outline change (a faint 0.15 ring alone fails the 3:1 focus-indicator floor).
- `--color-aqua-ring: rgba(0,232,208,0.15)` — focus/success parallel, same pairing rule.
- `--color-stage-fallback → var(--color-text-muted)` — replaces `StageBadge.tsx:81` `#b3b3b3`.
- **Semantic aliases:** `--color-action-primary → aqua`, `--color-action-danger → coral`, `--color-state-success → #22c55e`, `--color-state-warning → #ffb020`, `--color-state-error → #ff6b6b`. Components reference semantics; raw accents stay the source of truth.

**Light-theme status overrides (NEW, axe-gated):** verified `#15803d` (4.8:1 on `#f5f5f7`), unverified `#b45309` (4.6:1), error `#b91c1c`. **Contrast-floor rule:** all `--surface-*` alphas composite over a variable backdrop; text contrast (AA 4.5:1) must be validated against the *composited* background, especially muted text on `surface-1` over a bright wrap-poster image.

### 5.2 Typography — 7 named roles bound to the existing px ramp

Same families (Space Grotesk body `-0.01em`; Syncopate display `0.06em`), same ramp (10/12/14/16/18/20/24/32/48). The fix is *usage discipline*. **11px and 13px are banned going forward — round to 12 or 14.** Roles live in `@festie/shared/src/tokens/typography.ts` so a "title" is 20px on both platforms.

| Role | Family / Size / LH / Tracking | Replaces (verified) |
|---|---|---|
| `display-xl` | Syncopate 48 / 1.15 / 0.06em | wrap poster, FM hero |
| `display-lg` | Syncopate 32 / 1.15 / 0.06em | page titles |
| `heading` | Syncopate 24 / 1.15 / 0.06em | gives admin the primary/secondary tier it lacks |
| `title` | Space Grotesk 20 / 1.3 / -0.01em SemiBold | `SetCard.tsx:269` arbitrary `text-xl tracking-[-0.4px]` |
| `body` | Space Grotesk 16 / 1.5 / -0.01em | — |
| `label` | Space Grotesk 14 / 1.5 Medium | admin secondary headings, form labels |
| `caption` | Space Grotesk 12 / 1.4 | `SetCard.tsx:293` `text-[13px]` time row |
| `micro` | 10 / 1.4 / 0.08em UPPERCASE | `SetCard.tsx:257,279` stray `text-[11px]` (badge text only) |

> **Migration rule (mitigates the pixel-rhythm risk):** land the role map first with *unchanged pixel values per view*, then migrate one view at a time, verifying against the `cards-mobile-390` baseline screenshots the audit flags as pixel-sensitive.

### 5.3 Spacing, Radii, Density

- **Spacing:** unchanged 4px scale `--space-1..12` (4–48px). Migration is *enforcement*, not redefinition.
- **Density dial (two named modes, driven by existing tokens):** `comfortable` (desktop default — card `space-5`, grid gap `space-5`, section `space-8`); `compact` (mobile <640px + admin tables — card `space-4`, gap `space-3`). **Touch-safety guard:** compact must keep adjacent interactive targets ≥24px apart edge-to-edge (WCAG 2.5.8) even at `space-3` gaps; trigger compact on `pointer:coarse`-awareness, not width alone, so large touch tablets don't get sub-44px rows.
- **Radii / Z-ladder:** unchanged. `xs4 / sm8 / md10 / DEFAULT12 / lg20 / pill999`; `base0 / sticky10 / dropdown100 / overlay1000 / modal2000 / toast3000`.
- **Elevation (NEW — supports the sticky decision):** `--shadow-sticky: 0 1px 0 rgba(255,255,255,0.04), 0 4px 12px rgba(0,0,0,0.35)` (dark) / `0 1px 3px rgba(0,0,0,0.10)` (light). Applied to the day-tab subheader and sticky timeline legend so the raised `--color-bg-sticky` band reads as a toolbar above content.

### 5.4 Motion — keep the unified system verbatim

Easing `ease-out (0.16,1,0.3,1)`, `ease-spring (0.34,1.56,0.64,1)`, `ease-standard (0.4,0,0.2,1)`. Durations `fast120 / med200 / slow320`. Stagger 40ms. `press-scale(0.97)` universal tap.

**Consistency fixes only:** (1) `StageBadge.tsx:17` `duration-250` → `duration-med` (200ms is in the set; 250 is not). (2) **Web reduced-motion is already correct** — keep the existing global `*` catch-all (`animations.css:108-117`); do not hand-roll per-keyframe wraps. (3) **RN motion:** ease tokens → `Easing.bezier`; live-dot + priority-tap → Reanimated `withTiming/withRepeat`, **each gated on `AccessibilityInfo.isReduceMotionEnabled`** (this is the real reduced-motion gap, RN-only). **Note:** Reanimated is *not* currently installed in mobile/shared — adding it is an Expo prebuild step, scoped under P2, not a token swap.

## 7. Desktop vs Mobile

**One token table, two clients.** The shared `@festie/shared/tokens` (raw numbers, hex, bezier tuples) is the contract; web renders via Tailwind `@theme` vars, Expo via cached `StyleSheet`.

**Desktop (canonical surface, changes least):** left-rail view-switcher (Cards/Grid/Timeline/Festival/Picks/Compare/Wrap + Admin) with `heading`-role labels; sticky day-tab subheader with corrected aqua underline; `comfortable` density. Card grid `repeat(auto-fill, minmax(260px, 360px))` so cards cap at ~4 cols and never stretch illegibly on 1920px+. DetailPanel as centered modal at `lg:` with the max-width clamp.

**Responsive web <640px:** `compact` density, single-column everything; cards stack full-width at `space-4`; day tabs + search get guaranteed `space-3` horizontal rhythm (fixes 320px cramping); DetailPanel = vaul bottom sheet; admin tables collapse to stacked cards; account settings 6 sections → accordion.

**Expo app:** the same token *numbers* drive native rendering through the new hook — a "title" is 20px, a coral priority pill is `#ff3366`, an aqua focus is identical constants on both platforms. Bottom tabs keep file-based routing; the segmented "View" control surfaces schedule-shaped views without new tabs. **Honest scope:** the mobile app is a 4-tab shell today, so much of the mobile work is *building features*, not restyling — this is P1/P2, sequenced after the web token pass.

## 9. Open Questions & Risks

**Resolved decisions (product sign-off, 2026-05-28):**
1. **`--color-bg-sticky` direction → ELEVATE (lighter).** Sticky headers read as a raised toolbar: `#14142a` on dark (lighter than the `#080810` canvas) paired with `--shadow-sticky`. The old "recede" value `#05050c` is dropped. Tokenized once, no second migration.
2. **Sunlight legibility → YES, pulled to P1.** A dedicated **Daylight/Boost mode** (a third, high-contrast theme with brighter surfaces + max-contrast text + a one-tap header toggle) is committed and moved earlier into P1 — see backlog item 12b. This closes the one field-legibility gap Stagelight otherwise defers.
3. **NOW-moment emphasis → BOOST (P2).** The LiveBadge / timeline NOW indicator gains visual weight: bolder live badge + label, a higher-contrast indicator, and a sticky "NOW" anchor / jump-to. Scheduled as P2 (backlog item 20).

**Risks and mitigations:**
