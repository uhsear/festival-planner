# Tech-Debt Remediation Plan — 2026-05-29

**Repo:** festie (v3.0.0) — pnpm/turbo monorepo · backend (TS/tsx + Express + PG + Redis), web (React 19 + Tailwind v4 + TanStack), shared, mobile (Expo).
**Baseline:** Production LIVE (festie.us), CI ALL GREEN (9 jobs). 2931 backend tests, 632 web, 406 shared.
**Constraint:** Do not break green CI or production.

---

## Executive Summary

Five parallel audits (backend, web, shared+mobile, deps/supply-chain, config/infra, tests) produced ~50 findings. The codebase is in good health: strict TS everywhere, no `@ts-ignore`, solid transaction patterns, good a11y, healthy bundles. **No critical security vulnerabilities** in first-party code; the 15 moderate npm-audit advisories are all transitive (firebase-admin / socket.io / @google-cloud cascades).

The debt clusters into:

1. **Hygiene & dead code** (safe, high-volume): missing `.gitattributes` (root cause of recurring CRLF/LF churn — cited by 3 separate audits), 16 SQL-format lint warnings, unused web component + 11 dead style exports + 2 unused runtime deps, an unused root dependency (`swagger-ui-express`), and a stale knip config that mis-scopes `.js` instead of `.ts`.
2. **Config correctness** (mostly safe): dual npm+pnpm lockfiles, incomplete root `pnpm-workspace.yaml`, tilde-pinned security-sensitive deps.
3. **Robustness & scaling** (needs-care/risky): festival `hardDelete()` not transaction-wrapped, N+1 query patterns in admin/share paths, single-fork PM2 limitation, TS 5.8→6 root alignment, the firebase-admin/uuid security bump.
4. **Test quality** (mixed): one flaky time-dependent test, brittle SQL-substring assertions, timeout-based debounce waits, coverage-threshold gaps between backend (80/60) and web/shared (40/35).

The big lever is **`.gitattributes` with `eol=lf`** — it removes the noise source that keeps re-touching the SQL stores and inflating diffs on Windows. It is trivial and safe and should land first.
