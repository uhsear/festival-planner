# Festie Improvement Audit — 2026-06-05

Six review lenses (design/anti-slop, accessibility, frontend quality, reliability/silent-failures, performance, mobile UX) produced **34 verified findings**, of which **3 are High**, **11 Medium**, and **20 Low**. Two clear themes dominate: (1) a well-built design-token / shared-icon system that several web components quietly bypass with hardcoded literals (easing curves, stale brand hex, off-ramp font sizes, inline rgba), and (2) the offline/realtime reliability layer breaking its own "no silent drops" contract in three places — the highest-stakes cluster given that festivals are the no-signal scenario the queue exists for. Mobile contributes a consistent sub-44px touch-target and keyboard/foreground-resync gap set; accessibility surfaces real AA contrast and double-announce issues. No duplicate findings survived dedupe across lenses, though the stale-brand-hex token drift was independently confirmed by both the design and frontend-quality lenses (merged below).

## Findings by dimension

### Reliability / silent failures

- **[High] 24h queue-age prune silently discards stale offline writes** (`packages/shared/src/services/offlineQueue.ts:52-60`; `packages/web/src/hooks/useOfflineQueue.ts:163,206-240`) — Native `readQueue` and web `getAll`/`pruneStaleEntries` drop any entry older than `MAX_QUEUE_AGE_MS` with no `addFailedSync`, log, or banner, breaking the file's own "no silent drops" header contract; at a >24h-no-signal festival a day-1 write vanishes by day-2 and the pending count silently drops. **Fix:** route each dropped `QueuedMutation` through `recordFailed` / `useUIStore.addFailedSync` (error "Could not sync (older than 24h)") and/or `log.warn` with clientId+url so it stays visible in PendingSyncSheet.
- **[High] `updateMyStatus` optimistic upsert has no rollback on online server rejection** (`packages/shared/src/stores/crewStore.ts:1099-1150`) — Optimistically upserts the caller's own status row before the await; on an online rejection the catch only does `set({ error })` and rethrows, so the user keeps seeing their rejected "on my way / ETA X" until a later `loadCrewStatus`. `savePick` (festivalDataStore.ts:286,321) already models the correct snapshot/restore. **Fix:** capture `const prevStatuses = get().crewStatuses` before the optimistic set and restore it in catch (`set({ crewStatuses: prevStatuses, error })`); the offline synthetic path returns at l.1136 without throwing, so only the online path rolls back.
- **[Medium] Native `drainQueue` has no transient-retry cap** (`packages/shared/src/services/offlineQueue.ts:188-225`; `QueuedMutation` type ll.26-34) — Only permanent 4xx reach `recordFailed`; a persistently 500-ing write stays queued forever with no attempt counter, leaving an unclearable pending count. Web caps at `MAX_RETRIES=5` then surfaces (useOfflineQueue.ts:397), so this is a native/web parity gap. **Fix:** add a `retries` counter to `QueuedMutation`, increment on each transient failure, and at the cap (match web's 5) remove from queue AND `recordFailed(m, ...)`.
- **[Medium] Socket ack-timeout fires silently — no log and no client response** (`routes/socket.ts:98-113`) — On timeout the callback only sets `called=true` ("Log but don't call respond") with no log statement, and `withAckTimeout` is module-level so the destructured `log` isn't even in scope; a slow `join:festival`/`join:crew`/`reconnect:restore` produces zero telemetry and never delivers an ack. **Fix:** pass the logger into `withAckTimeout`; on timeout `log.warn('socket ack timeout', { connectionId })` and `respond({ ok: false, error: 'Server timeout', code: 'WS_ACK_TIMEOUT' })` before setting `called=true`.
- **[Medium] `setSocketPresence` failure downgraded to `log.debug` — member silently missing from presence** (`routes/socket.ts:196-198`) — A failed Redis presence write logs at debug (below prod level) and `emitPresence` runs anyway on the stale set, so the user joins the room but is absent from the who's-online list with no prod-visible warning. **Fix:** raise to `log.warn`/`error` with festivalId+userId, and consider re-emitting after retry or reflecting the failure in the join ack.
- **[Low] `markOnlineAndDrain` web drain is a floating promise with no `.catch`** (`packages/shared/src/services/api.ts:201-202`) — `void window.__festieQueue.processQueue();` lacks error handling while the native sibling (l.204) uses `.catch(() => {})`; latent unhandled-rejection risk if the bridge throws early (processQueue's own try/catch at useOfflineQueue.ts:434-439 keeps it inactive today). **Fix:** mirror native — `void window.__festieQueue.processQueue()?.catch(() => {})`.

### Performance (web + shared + backend)

- **[High] Each SetCard runs its own 60s `setInterval`** (`packages/web/src/hooks/useSetStatus.ts:26-32`, used in `SetCard.tsx:107`) — Per-instance `setInterval(60000)` calls `setNow` + re-runs `getSetStatus`; in the unvirtualized Cards view a 100–200 set day mounts that many unsynchronized timers, smearing re-renders across the minute and dragging INP/battery on mid-range Android. **Fix:** one shared clock — module-level interval + `useSyncExternalStore` `useNow()` hook (timeline.tsx:55-59 already does this for `nowMs`). Compounds with the unvirtualized cards finding.
- **[Medium] Cards view renders all sets unvirtualized** (`packages/web/src/routes/cards.tsx:159-193`) — `filteredSets.map` mounts every set as a SetCard (multiple zustand selectors + the per-instance interval) with no windowing; all re-evaluate selectors whenever `allProfiles`/`currentProfile` change (e.g. a realtime crew pick). Mobile virtualizes the same data via FlatList. **Fix:** virtualize (react-virtuoso / react-window); interim quick win — `content-visibility:auto` + `contain-intrinsic-size` on the per-card wrapper (cards.tsx:166).
- **[Medium] TimelineGrid rebuilds hundreds of static background/time cells per render** (`packages/web/src/features/TimelineGrid.tsx:139-186`, not memoized at line 39) — Plain function component re-renders on every parent render (each pick toggle → new `conflictIds` Set; each 60s tick), regenerating `totalSlots` time-label divs + `visibleStages*totalSlots` background cells that depend only on stages/timeBounds/rowHeight. Set blocks are memoized; this background layer is not. **Fix:** extract the static grid into a `React.memo` subcomponent keyed on visibleStages/timeBounds/rowHeight/vpW, or replace per-cell divs with a single `repeating-linear-gradient`.
- **[Low] Crew-overlap map (`othersBySet`) churns on every own-pick toggle** (`packages/web/src/features/TimelineGrid.tsx:75-79`; `packages/shared/src/hooks/usePicks.ts:94-106`) — `getOtherPicks` is `useCallback([currentProfile, allProfiles])` but reads only `currentProfile.id`; toggling your own pick flips the whole-object identity, invalidating `othersBySet` and re-looping every timed set. **Fix:** depend on `currentProfile.id` instead of the whole object (same pattern in cards.tsx).
- **[Low] Fonts loaded from Google Fonts CDN via render-blocking stylesheet** (`packages/web/index.html:12-19`) — Space Grotesk (4 weights) + Syncopate (2) load from fonts.googleapis.com; line 19 is a render-blocking `<link rel=stylesheet>` adding third-party DNS/TCP/TLS on the critical path (size-adjust fallback covers CLS, not LCP). **Fix:** self-host WOFF2 subsets with local `@font-face`, or load non-blocking (media=print + onload swap); drop unused weights.
- **[Low] Topic-subscription update writes one row per topic in an awaited loop** (`routes/notifications.ts:306-308`) — Serial `setSubscription` per topic inside `Object.entries` (bounded by `ALLOWED_TOPICS`, small N). **Fix:** batch into one multi-row `INSERT ... ON CONFLICT` upsert, or at minimum `Promise.all` the writes.

### Accessibility (WCAG/APCA, web + mobile)

- **[Medium] Mobile priority pick buttons are 40×40, below the 44px sibling target** (`packages/mobile/components/SetCardMobile.tsx:426-428`, rendered via PriorityButton l.112) — The most-tapped schedule control, three adjacent, with no `hitSlop`; siblings `dayChip`/`filterChip` set `minHeight:44` and web uses `w-11 h-11`. Passes WCAG 2.5.8 AA (24px) but fails 2.5.5 AAA / Apple HIG. **Fix:** set width/height 44, or add `hitSlop` of 2 per side.
- **[Medium] Deselected mobile stage-filter chip dims its label via opacity 0.6, failing AA** (`packages/mobile/app/(tabs)/index.tsx:754-758` filterChipOff, `766-768` filterChipTextOff) — `text.muted` (#8787a8) under 0.6 opacity over #080810 composites to ~#54546b ≈ 2.7:1, below the 4.5:1 AA floor for sub-18px text; chip stays interactive (not disabled-exempt) and the inline "above AA" comment is contradicted by the math. **Fix:** drop opacity, recess via dimmer background/border, and set `filterChipTextOff` to `text.secondary` (#9999bb) which clears 4.5:1; confirm the stage dot still reads 3:1+.
- **[Medium] Mobile Switch and Live header chips are ~24px tall with no hitSlop** (`packages/mobile/app/(tabs)/index.tsx:649-658` switchButton, used at 415/425) — `paddingVertical spacing[1]` around a 14px icon+label gives ~24px height; both TouchableOpacity instances omit `minHeight`/`hitSlop` unlike the day/filter chips and SegmentedControl. At the 2.5.8 boundary, fails 2.5.5 AAA. **Fix:** add `minHeight:44` to switchButton or `hitSlop` to both TouchableOpacity instances.
- **[Low] Inactive web stage chip computes text contrast against the canvas, not the tinted pill** (`packages/web/src/components/ui/StageBadge.tsx:117-122`, helper 95-108) — The faded chip sets `stageColor+'20'` over the dark canvas but `ensureDarkBgContrast` solves only against `getDarkBgLuminance()`, never compositing the tint; bright stages stay ~10:1, but dark stages brightened to exactly 4.5:1-on-canvas land ~4.0–4.3:1 on the pill — a small edge-case dip. **Fix:** composite `stageColor+'20'` over `--color-bg-primary` and solve against that, or use a neutral recessed background token and keep the stage color on dot/border only.
- **[Low] Web SetCard announces each set twice to screen readers** (`packages/web/src/components/features/SetCard.tsx:278` button aria-label vs `307/320/347` visible spans) — The full-card button's aria-label reads artist/stage/start while the visible stage/artist/time spans are only `pointer-events-none` (not `aria-hidden`), so a screen reader reads the set twice; the button label also omits the end time. **Fix:** add the end time to the button aria-label first, then mark the decorative spans `aria-hidden`.

### Design / anti-AI-slop (hallmark + Rams)

- **[Medium] Onboarding modal is a generic AI macrostructure** (`packages/web/src/components/features/Onboarding.tsx:33-52,112-167`) — Textbook slop: centered card + circular icon-in-a-ring (Sparkles/Music/Users single glyphs) + generic marketing copy ("Your crew coordination hub for festivals…"); Sparkles is the emoji-as-feature tell. **Fix:** lead step 1 with a real mini lineup preview (2–3 actual set cards) instead of the Sparkles circle, make copy concrete ("Tap a set to mark it Must-See, Want, or Maybe"), drop the Sparkles glyph, trim to 2 steps. *(The "auto-opens over a PAST festival" sub-claim is not code-backed — visibility is purely the `festie_onboarding_completed` localStorage flag — treat as a separate nice-to-have.)*
- **[Medium] Two icon vocabularies mixed: Lucide vs raw Unicode/emoji** (`packages/web/src/components/features/SetCard.tsx:303,360,372,389-391` vs `components/layout/SubHeader.tsx:215`) — Lucide is the library, yet priority = ★◆●, Spotify preview = ▶/◼, conflict ⚠ + note 📝 render as raw glyphs; sharpest tell is the SubHeader "My picks" Lucide `<Star>` sitting beside SetCard's Unicode ★ — one concept, two renderings, one screen. **Fix:** pick one vocabulary (swap glyphs to Lucide Star/Diamond/Circle/Play/Square/AlertTriangle/StickyNote, or switch the filter to Unicode ★) and centralize the priority icon map in `@festie/shared` so web/mobile can't drift.
- **[Low] `transition-all` on the shared Button (and others) violates animate-only-transform/opacity** (`packages/web/src/components/ui/Button.tsx:27`) — `transition-all duration-200` on the most-reused primitive animates layout/border/box-shadow too; SetCard.tsx:294 already models the correct explicit-property pattern. **Fix:** replace with an explicit list e.g. `transition-[color,background-color,border-color,box-shadow,transform,outline-color] duration-200`; apply to Button first, then Card/StageBadge.
- **[Low] Inert decorative `bg-clip-text` gradient on every artist name across ~50 cards** (`packages/web/src/components/features/SetCard.tsx:324-327`) — The two stops differ only by 15% alpha of the same near-white and there's no `text-transparent`, so the gradient is doubly inert while still forcing a clipped-text background paint on every card. **Fix:** delete the gradient + bg-clip-text, use the solid `text-text-primary` token.
- **[Low] Uniform `hover:scale` on unrelated sibling controls** (`packages/web/src/components/features/SetCard.tsx:295,406`; `DetailReminderPicker.tsx:19`; `DetailPriorityPicker.tsx:25`) — Spotify preview, every priority dot, and both segmented pickers all balloon on hover — undifferentiated interaction rather than one meaningful affordance. **Fix:** reserve scale for the single primary affordance and express the rest via background/border-color; at minimum drop `hover:scale` on the priority dots.

### Frontend UI engineering quality (web)

- **[Low] Stale/incorrect brand-color hex fallbacks in inline `var()` calls** *(found by both Design and Frontend-quality lenses)* (`packages/web/src/components/timeline/TimelineLegend.tsx:40,44,48,53,64`; `routes/timeline.tsx:207,209,242,243`; `features/TimelineGridCell.tsx:118-120`; `features/TimelineGrid.tsx:151`; `styles/base.css:214-215,227`; `styles/theme.css:58,68,121`) — Canonical tokens are coral #ff3366 / aqua #00e8d0 / amber #ffb020 / bg-primary #080810, but inline `var()` fallbacks (and the skip-link, and theme.css itself) carry the OLD hex #ff6b6b / #00d4aa / #f59e0b / #0d0d1a; dead today but would paint off-brand if a var ever failed to resolve. **Fix:** drop the literal fallbacks (tokens are defined at `:root` so they always resolve) or use the generated semantic utilities; a repo-wide search for `,#` inside `var()`/className strings surfaces all instances, including the theme.css self-occurrences.
- **[Low] Hardcoded easing curve bypasses the centralized `--ease-out` token** (`packages/web/src/components/ui/Button.tsx:27`; `Card.tsx:14`; `SetCard.tsx:246,405`; `TimelineGridCell.tsx:72`; `TimelineGrid.tsx:232`; `TBASection.tsx:64`; `routes/timeline.tsx:248`) — theme.css:282 defines `--ease-out: cubic-bezier(0.16,1,0.3,1)` "so a tuning pass updates one number," yet 8 spots hardcode the literal, including Button/Card; byte-identical today so no visual diff, purely future-maintenance risk. **Fix:** replace every `ease-[cubic-bezier(0.16,1,0.3,1)]` with the `ease-out` utility (one find/replace).
- **[Low] Off-ramp ad-hoc font sizes despite the canonical type ramp** (`packages/web/src/components/features/SetCard.tsx:336,366`; `TimelineGridCell.tsx:134,137,148,166`; `DetailPanel.tsx:300,347,364`; `routes/timeline.tsx:244`; `UserMenuProfileCard.tsx:62,65,67,76,85,86,89,102`) — theme.css:178 says "use these instead of ad-hoc text-[Npx]," yet text-[11px] (8× in UserMenuProfileCard), text-[12.5px], text-[13px], text-[15px] sit off the scale, making secondary text inconsistent across cards/timeline/detail. **Fix:** snap each to the nearest role; if 11/13px steps are genuinely needed (they recur), add `--font-size-11/-13` + matching `type-*` roles so they're themable.
- **[Low] Missing coral (and aqua-0.25) alpha token steps force inline `rgba()`** (`packages/web/src/components/features/SetCard.tsx:367,368,415,499,510`; `AppShell.tsx:153`) — A mix: coral `rgba(255,51,102,0.3)` (368,415) is genuinely tokenless; coral 0.15 (367) duplicates existing `--color-coral-ring`; aqua 0.15 (499,510) should reuse existing `--color-aqua-a15`; aqua `rgba(0,232,208,0.25)` (AppShell:153) is genuinely missing (scale jumps a2→a3). **Fix:** add `--color-coral-a3` and `--color-aqua-a25` (plus a coral-a15 alias), then replace all six literals, reusing `--color-coral-ring` / `--color-aqua-a15` where they exist.
- **[Low] DetailPanel note state is not keyed to the set — notes can render stale on set change** (`packages/web/src/components/layout/AppShell.tsx:172-178`; `DetailPanel.tsx:56-57`) — `<DetailPanel set={detailSet}/>` has no `key`; `personalNote`/`crewNote` seed from `useState(...notes?.[set.id])` with no re-sync `useEffect`, so a `detailSet` swap while mounted keeps the prior set's text (latent today — every open path closes the panel first). **Fix:** add `key={detailSet.id}` to force a clean remount (also resets Spotify/visible state).
- **[Low] Empty priority buckets each render a full EmptyState, recreating the "stuck" look** (`packages/web/src/routes/picks.tsx:250-313`, esp. 291-310) — Once `totalPicksThisDay>0`, all three sections render and each empty bucket shows an icon+title+description block — the exact stacked-hint pattern the global-empty branch comment (218-225) says was replaced because it "looked like broken/stuck UI" (the per-bucket variant is smaller but the pattern remains). **Fix:** collapse empty non-global buckets to a single muted helper line, or show just the header with a 0 badge.
- **[Low] Bare "Loading..." route fallback instead of the existing skeleton library** (`packages/web/src/components/layout/AppShell.tsx:74-81,131-143`) — Both route-level Suspense fallbacks render literal "Loading..." text in the auto-fill grid, while the project ships `{Grid,Timeline,Picks,Crew}Skeleton.tsx` used for data loads elsewhere; fires only on code-split chunk load (brief). **Fix:** replace with a centered branded loader or route-aware skeletons.

### Mobile UX & web parity (Expo/RN)

- **[Medium] Account settings forms have no keyboard avoidance or focus-chaining** (`packages/mobile/app/(tabs)/account.tsx:90`; `components/AccountPasswordSection.tsx:100-140`) — Plain ScrollView hosting display name, payment handles, and a 3-field password change; no `KeyboardAvoidingView`, no `keyboardShouldPersistTaps` (defaults to 'never', so the first "Update Password" tap only dismisses the keyboard), and the secureTextEntry fields have no refs/returnKeyType/onSubmitEditing/blurOnSubmit. crew.tsx:515-527 does it correctly. **Fix:** wrap in `KeyboardAvoidingView` (behavior padding/height by platform) + `keyboardShouldPersistTaps="handled"`; add refs to chain current→new→confirm with `returnKeyType='next'/'go'` and `blurOnSubmit={false}`.
- **[Medium] Timeline set blocks are 18–40px tall — below 44px, no hitSlop** (`packages/mobile/components/TimelineView.tsx:23` ROW_HEIGHT=22; set-block TouchableOpacity 158-176) — `Math.max(ROW_HEIGHT, …)-4` yields an 18px target for a 15-min set, ~40px for 30-min; the block is the only interaction (no inline pick affordance) and has no hitSlop, so short B2B/opener slots are hard to tap. **Fix:** add `hitSlop={{ top: 8, bottom: 8, left: 4, right: 4 }}` and/or clamp the `Math.max` floor toward 44px.
- **[Medium] "Live" time-based screens don't re-sync on app foreground** (`packages/mobile/app/festival-mode.tsx:55-58` 60s interval; `hooks/useNowIndicator.ts:28-31` 30s tick; `TimelineView.tsx:250` 60s tick) — iOS suspends JS timers while backgrounded and none of these have an AppState listener, so reopening at the festival (the primary use case) shows stale "now playing / up next" and NOW line until the next tick fires. **Fix:** add an AppState 'active' listener that calls `setNow(new Date())`/`setNowTick(Date.now())` immediately on resume, alongside the interval.
- **[Low] Haptics wired on only ~3 surfaces; high-signal crew/nav actions are flat** (`hooks/useHaptics.ts` consumed only in `SetCardMobile.tsx` and `app/set/[setId].tsx`; absent in `CrewStatus.tsx`, `CrewPolls.tsx`, `CrewExpenses.tsx`, `app/(tabs)/_layout.tsx` tab presses, day selector `index.tsx:481`) — The platform-correct hook exists but crew status change, poll vote, expense add/settle, tab switch, and day select give no tactile feedback (plan-share.tsx fires haptics via a direct expo-haptics import, not the hook). **Fix:** call the existing hook — `haptics.select()` on toggles, `haptics.success()` on successful mutations, `haptics.warning()` on a detected clash. No new deps.
- **[Low] Schedule search list doesn't dismiss the keyboard on scroll** (`packages/mobile/app/(tabs)/index.tsx:549-568` cards FlatList vs search TextInput at `index.tsx:446`) — The cards FlatList sets `keyboardShouldPersistTaps='handled'` but no `keyboardDismissMode`, so scrolling results keeps the keyboard up covering half the list; crew.tsx:527 already uses `on-drag`. **Fix:** add `keyboardDismissMode="on-drag"` to the schedule cards FlatList.

## Notes & caveats

- **Needs human design judgment** (not code-mechanical): the Onboarding macrostructure rewrite, the icon-vocabulary choice (geometric ★◆● as intentional brand language vs Lucide), the empty-bucket pattern, and the `hover:scale` differentiation are taste/brand calls — confirm direction before implementing.
- **Lower-confidence / latent findings flagged by reviewers:**
  - StageBadge faded-chip contrast (Low confidence) — the original "broad failure" claim was corrected to a small dark-stage-only edge-case dip; bright stages are fine (~10:1). Verify against the specific dark stage palette before changing.
  - DetailPanel note-key and `markOnlineAndDrain` floating promise are **latent, not active** — guarded by current open-path/try-catch behavior; cheap defensive fixes, not live bugs.
  - `updateMyStatus` bad state **self-heals** on the next `loadCrewStatus`, and the 24h-prune bug requires a genuine >24h-offline window — both real, but neither is a permanent corruption.
- **Corrections folded in during verification (for the fixer's awareness):** easing occurrences are **8**, not 10; the mixed-icon divergence lives entirely in **web** (only the icon-map centralization touches shared); the coral-alpha finding mixes truly-missing steps (coral-0.3, aqua-0.25) with existing-but-unused tokens (coral-ring, aqua-a15); `useNowIndicator` ticks at **30s** not 60s.
- **Dropped by reviewers (out of scope):** the mobile OfflineMap Leaflet-in-WebView is a **deliberate** offline-tile tradeoff (offline = #1 product priority) — by-design, not a finding.
