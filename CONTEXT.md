# Festie

Real-time festival crew coordination app where friends plan which performances to see, coordinate meetups, and share expenses at music festivals.

## Language

### Core entities

**Festival**:
The top-level event entity representing a multi-day music festival with a lineup, stages, and schedule.
_Avoid_: event, show, concert

**Stage**:
A named physical performance location within a festival (e.g. "Main Stage", "Tent B"), displayed as a column in the grid view.
_Avoid_: venue, area, workflow state

**Set**:
A single artist performance in a specific timeslot on a specific stage. The atomic unit of the festival schedule.
_Avoid_: slot, performance, gig, show, data structure

**Artist**:
A performer within a set. A set has one or more artists; multi-artist sets are displayed joined by a b2b separator.
_Avoid_: act, band, performer

**Day**:
A logical festival day identified by a zero-based `dayIndex`. Days can span past midnight (sets before 6 AM belong to the previous day).
_Avoid_: date (ambiguous with the calendar date string)

### User & identity

**User**:
A registered account with username, password, and optional avatar. Global identity across all festivals.
_Avoid_: account (when referring to the person)

**Profile**:
A user's per-festival participation record (`festival_profiles`). Holds that user's picks, notes, and reminders for one festival. One user has one profile per festival.
_Avoid_: user account, settings, preferences

### Schedule interaction

**Pick**:
A user's selection of a set they want to attend, stored as a set ID mapped to a priority level on their profile. Not a ticket or vote.
_Avoid_: selection, bookmark, favorite, vote, ticket

**Priority**:
The importance level assigned to a pick: `must`, `want-to-see`, or `maybe`. Drives visual styling (coral, aqua, amber) and sort order.
_Avoid_: rank, tier, rating

**Note**:
A free-text annotation a user attaches to a specific set within their profile. Personal and private.
_Avoid_: comment, review

**Reminder**:
A notification preference tied to a set, specifying how many minutes before the set to alert the user.
_Avoid_: alarm, alert

**Rating**:
A 1-5 post-festival score a user gives a set they attended, with an optional text note. Distinct from a pick (pre-festival intent) or a note (personal annotation).
_Avoid_: review, score

**Conflict**:
Two picked sets whose time ranges overlap, making it impossible to attend both. Detected client-side and surfaced as warnings.
_Avoid_: clash, overlap (which means something different in crew context)

### Crew system

**Crew**:
A named group of friends coordinating at a festival. Has an owner, members, an invite code, and a max member cap (default 30). Scoped to one festival.
_Avoid_: team, group, squad, staff, roadies

**Invite Code**:
A short alphanumeric code used to join a crew. Generated server-side, expires after 7 days, and can be regenerated by the crew owner.
_Avoid_: join code, access code

**Overlap** (crew context):
The computed intersection of picks across crew members for a given set -- how many crew members picked the same set and at what priority.
_Avoid_: intersection, match, conflict

**Home Base**:
A crew-level meeting location and time (e.g. "by the fountain at 2 PM"). A single persistent rendezvous point for the crew.
_Avoid_: headquarters, camp

**Meeting Point**:
A typed, time-bound rendezvous created by any crew member. Has a type (`emergency`, `pre-show`, `during`, `post-show`, `post-event`), optional stage reference, and expiry.
_Avoid_: pin, waypoint, marker

**Expense**:
A shared cost tracked within a crew. Records who paid, the amount, a description, a category, and which members to split with.
_Avoid_: bill, payment, transaction

**Poll**:
A crew-scoped question with multiple options that members vote on (e.g. "Which after-party?").
_Avoid_: survey, vote

**Activity**:
The crew's chronological feed of events: member joins, picks, expense additions, home base updates, meeting point changes. Stored in `crew_activity`.
_Avoid_: feed, log, chat, timeline (which is a schedule view)

### Schedule views

**Grid**:
The matrix schedule view. Stages as columns, time as rows, sets as positioned blocks. Supports pixel-per-minute scaling by viewport width.
_Avoid_: table, matrix, spreadsheet

**Timeline**:
The chronological vertical schedule view. Sets grouped by time slot with stage badges, sorted within slots. Shows one day at a time.
_Avoid_: feed, list view, activity (which is a crew concept)

**Cards**:
The swipeable card-based schedule view. Each set rendered as a card sorted by hotness (temporal proximity), then time, then artist name.
_Avoid_: tiles, list, swipe view

**Picks view**:
The filtered view showing only the current user's picked sets, grouped by priority level (must / want-to-see / maybe).
_Avoid_: my schedule, favorites

**Compare**:
The crew schedule comparison matrix. Rows are sets on the selected day that any crew member picked; columns are crew members. Cells show each member's priority.
_Avoid_: diff, side-by-side

**Festival Mode**:
A live-day UI mode that shows a countdown to upcoming picked sets, auto-scrolls to "now", and hides past sets. Activates when the festival date range includes today.
_Avoid_: live mode, day-of mode

**Wrap**:
A post-festival summary view showing stats (sets rated, stages visited, days attended, total hours) and the user's top-rated sets. Only available after a festival ends.
_Avoid_: recap, summary, review

### Import & display

**B2B Separator**:
A per-festival string (default `"b2b"`) used to join multiple artist names in a set's display name (e.g. "DJ A b2b DJ B"). Configurable for festivals that use "vs", "&", etc.
_Avoid_: delimiter, joiner

**Lineup Import**:
The process of ingesting a festival's schedule data (stages, days, sets, artists) from an external source into the database.
_Avoid_: upload, sync

## Relationships

- A **Festival** has many **Stages**, **Days**, and **Sets**
- A **Day** belongs to one **Festival** and contains many **Sets**
- A **Set** belongs to one **Stage** and one **Day**, and has one or more **Artists**
- A **User** has one **Profile** per **Festival** they join
- A **Profile** has many **Picks**, **Notes**, and **Reminders**, each keyed by **Set** ID
- A **Pick** maps a **Set** to a **Priority** within a **Profile**
- A **Crew** belongs to one **Festival** and has many members (**Users**)
- A **Crew** has one **Home Base**, many **Meeting Points**, **Polls**, **Expenses**, and **Activity** items
- **Overlap** is computed from the **Picks** of all **Crew** members for a given **Set**
- A **Rating** is given by a **User** for a **Set** (post-festival)
- A **Conflict** is detected between two **Picks** in the same **Profile** whose **Sets** overlap in time

## Example dialogue

> **Dev:** "When a user opens the grid for Day 2, what data are we pulling?"
> **Domain expert:** "The **Sets** for `dayIndex: 1`, positioned by **Stage** (columns) and time (rows). If they have a **Profile**, their **Picks** are overlaid as colored blocks -- coral for must, aqua for want-to-see, amber for maybe."

> **Dev:** "What's the difference between crew overlap and a conflict?"
> **Domain expert:** "A **Conflict** is personal -- two of YOUR **Picks** that collide in time. **Overlap** is social -- it shows how many **Crew** members picked the same **Set**, so you can see where your friends will be."

> **Dev:** "Can a user have picks without a profile?"
> **Domain expert:** "No. A **Pick** lives inside a **Profile**, and a **Profile** is created when you join a **Festival**. No profile, no picks."

## Flagged ambiguities

- **"Profile"** could mean the user's global account or their per-festival data. In Festie, **Profile** always means the per-festival record (`festival_profiles`). The global identity is always called **User**.
- **"Stage"** in common software usage means a workflow phase. In Festie it is exclusively a physical performance location.
- **"Set"** is overloaded with the JavaScript `Set` data structure. In domain context it always means a performance timeslot. Code uses `FestivalSet` as the type name to disambiguate.
- **"Activity"** vs **"Timeline"**: **Activity** is the crew event feed (`crew_activity` table). **Timeline** is a schedule view showing sets chronologically. Never swap these.
- **"Overlap"** appears in two contexts: **Crew Overlap** (shared picks across members) and time overlap (used in **Conflict** detection). The crew concept is a feature; the time concept is a utility.
- **"Note"** vs **"Rating note"**: A **Note** is a private annotation on a set within a profile. A **Rating** also has an optional note field, but this is a post-festival comment attached to the rating, not the profile note.
